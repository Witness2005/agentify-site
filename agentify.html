Sheet 01 — el mecanismo

De repositorio a paquete de contexto

Un escaneo determinista alimenta a seis pasadas especializadas que corren en paralelo. Cada una escribe su propio documento; nadie más lo toca.

1 repo → 1 scan determinista → 5 pasadas en paralelo (+ standards-writer, que espera a repo-scout) → edición final validada.
Sheet 02 — el flujo, paso a paso

Cinco pasos, nada de bash de más

Todo el flujo pide permiso de Bash una sola vez: para correr el escáner. Las seis pasadas trabajan solo con Read, Glob, Grep y Write.

01

Gate — ¿aplica?

scan_repo.py --check decide si el directorio es un proyecto de desarrollo real. Si no lo es, la respuesta es exactamente not applicable y no se escribe nada.

02

Escaneo determinista

Un único scan_repo.py produce .agentify/scan.json: lenguajes, manifiestos, frameworks, entrypoints, capas, CI/CD, contenedores, variables de entorno y metadata de git. Se trata como hipótesis a confirmar, no como verdad absoluta.

03

Seis pasadas especializadas

Cinco corren en paralelo (repo-scout, architect, contract-mapper, ops-engineer, trap-hunter); standards-writer arranca cuando repo-scout entrega el inventario. Cada una escribe su propio archivo y responde con un resumen de una línea — el contenido nunca se duplica en el contexto del orquestador.

04

Edición final

Con esos resúmenes, el orquestador escribe AGENTS.md y overview.md — los dos únicos documentos que dependen de todo lo demás — y unifica el tono.

05

Validación

validate_agentification.py revisa estructura, front-matter completo, links relativos, que version coincida con el HEAD de git, el presupuesto de 200 líneas por documento y los placeholders sin rellenar.

Sheet 03 — las seis pasadas

Un especialista por documento

Sheet 04 — qué queda en el repo

El paquete de contexto

Ocho archivos, cada uno con un presupuesto de tamaño estricto — entre 60 y 200 líneas — para que citen file:line en vez de pegar código.

AGENTS.md identidad + orden de lectura (front-matter: app, archetype, criticality, slack_channel, on_call, version, validated) docs/agent/ ├── overview.md qué hace el repo, sus capacidades y dónde vive cada una ├── architecture.md capas, entrypoints, mapa del repo, flujo de datos ├── contracts.md qué expone y de qué depende ├── runbook.md build/run/test y Definition of Done ├── traps.md trampas tácitas que no se ven en el código ├── rules.md buenas prácticas de código para este stack └── security-rules.md reglas de seguridad
Sheet 05 — la regla que sostiene todo

Nada se inventa

¶

Todo lo escrito debe rastrearse a un archivo del repo, a la salida de un comando, o a algo que el usuario dijo explícitamente. Cuando algo no se puede verificar, el documento lo declara en vez de rellenarlo con una suposición plausible:

gap — confirm with <team>

Ese marcador es un entregable válido. Al cerrar, agentify reporta cuántos gap — quedan: esa lista es el cuestionario para el equipo dueño del repo.

Sheet 06 — instalación y uso

Dos formas de correrlo

Como plugin recomendado

Usa subagentes en paralelo — las seis pasadas corren de verdad al mismo tiempo.

# desde el directorio que contiene agentify-marketplace › /plugin marketplace add ./agentify-marketplace › /plugin install agentify@agentify-local # si el resumen lo pide: › /reload-plugins # uso › /agentify:agentify [path] [--dry-run]

Como skill independiente

Sin subagentes: las pasadas se ejecutan en secuencia, en un solo hilo.

# copiar la carpeta de la skill cp -r skills/agentify-repo/ \ ~/.claude/skills/agentify-repo/ # se activa sola al pedir # "agentifica este repo"
Los documentos generados siempre quedan en inglés — decisión fija del plugin, sin flag para cambiarla. personalización: references/templates.md, references/stacks.md, references/agents.md
